# Independent GEPA MATH candidate discovery V1

This is a separate external comparison against the seven completed opportunities
of `math_v2_2_gradient_pattern_seed81_pilot_v2`. Historical BBH baseline and
capacity-probe identities remain unchanged. The latest user task explicitly
authorizes this MATH adapter, seven-window protocol, one bounded real comparison,
and commits of adapters, tests, protocols and sanitized reports. It overrides the
older BBH-only stage defaults in AGENTS.md; no sibling source edits are permitted.

Official GEPA v0.1.1 is immutable. Use native reflection, epoch-shuffled training
minibatches, instance Pareto selection, strict local survival, native frontier,
archive and native best selection. One component is called `system_prompt` by
GEPA, but its text belongs in the A4 Solver user message. The immutable system
message and user suffix are preserved exactly. Merge is disabled as a supported
native setting to fit the local36 cap. This is explicitly a configured independent
GEPA reproduction, not a replication of paper benchmark results.

Seed81; ordered targets0,1,3,2,4,0,1; separate GEPA states and seeds81000..81006.
Every window starts from the byte-identical A4 minimal initial procedure.
The adapter exports only frozen Optimize60 from the sibling canonical source,
without importing sibling modules. Raw records for unselected rows are skipped.
Validation, Test and Shadow content is not exported. Historical initial member
profiles are frozen in a separate audit-only file, inaccessible to the adapter.
No historical manual instructions, solutions or diagnostic conclusions are used.

Every window uses native trainset=Optimize60 and native valset=six examples sorted
by the canonical hash of seed/window/stable example identity. The term native
valset here denotes Optimize search support; held-out Validation remains denied.
Reflection minibatch3, one-component round-robin, skip_perfect_score=false,
cache_evaluation=false, 36 logical metric cap and6 generated-proposal cap.
Before starting a reflective iteration reserve12 metrics for parent3, child3
and native val6. The reserve can terminate a window with unused metrics and
fewer than6 generations. It does not modify native acceptance or parent selection.
No efficacy-based rerun, seed extension, extra search window or budget extension.

Each window selects at most4 changed, contract-valid, actually Solver-evaluated
procedures: native best first, then native Pareto members by descending native
valset score and native index, then remaining generated procedures by hash and
generation. The last rule includes locally rejected procedures. Duplicate hashes
and the initial procedure are excluded from the changed pool. The initial
procedure is always Full60-evaluated separately, including when native best is
initial. All seven windows and all selection lists freeze before Full audits.
Audits never feed back to GEPA. No A4 TeamProbe or promotion rule gates them.

Native reflection template is unchanged except for a declared task-boundary
suffix preventing fixed answers, problem/solution copying and output-interface
modification. A bounded deterministic candidate guard enforces nonempty text,
3000 characters, obvious fixed-answer/interface violations and literal source
copying. Its limited semantic coverage is not a guarantee against all memorization.
Invalid candidates receive zero local scores without Solver dispatch and remain
excluded from audit selection; duplicate valid procedures can be evaluated and
count toward logical metrics. The guard and template enter source identity.

Solver and optimizer parameters are copied from the executed A4 binding, never
from generic CLI defaults. math-verify0.6.0, latex2sympy2_extended1.0.9,
sympy1.14.0, ANTLR4.13.2 and mpmath1.3.0 are required. The copied MATH workers
preserve exact parser and gold-first scoring code, with package-local imports.
Strict final-marker framing and four completed same-request invalid draws are
required; first valid wrong answer stops recovery. Every draw is charged.

Each window/member/attempt has a separate resolved-output cache. Identical
requests within that namespace may reuse original realizations across phases.
All logical evaluations count, including hits. Historical realizations are used
only as frozen peer measurements for post-hoc compatibility; historical Solver
cache entries never satisfy new provider requests. Fresh initial Full60 per
window measures baseline drift. Report original22 retention and fresh-parent
retention separately. V2.2 Optimize compatibility is not a Shadow safety pass.
The executed invalidity binding has no separate invalid-count rejection guard.

concurrency1, SDK retries0, transport retries20 with1.5-second exponential backoff

An interrupted run consumes the one-shot grant and cannot automatically restart.
