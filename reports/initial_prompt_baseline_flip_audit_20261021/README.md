# 原始 GPT-4o-mini Prompt 三次 Test 的 flip 审计

审计完成：2026-10-22（北京时间）。目录名保留审计启动日期。
范围是历史原始 Prompt baseline 的三份 Test300：**231、224、225 / 300**。
本次零模型 API、零新增测评输出，不修改原成绩、不修改运行配置、不启动实验。

**结论：这不是已经设置 temperature=0、top_p=1 后仍然不稳定的证据。**
实际付费请求使用 0.2 / 0.8。54 道题发生正确性 flip，主要能在模型的
可见解题输出中找到数学或题意理解差异；同时确有旧解析器缺陷及格式敏感性。
未发现本地 Prompt 构造随机化、few-shot 随机化或并发结果错位的证据。
这些结果不能量化 temperature 改成 0 后会剩余多少变化，也不能证明供应商
实际执行了其收到的采样参数。

## 2. 实际设置核对

| 检查项 | 实际历史证据 | 判断 |
|---|---|---|
| temperature=0 | 959 次请求全部为 **0.2** | 不满足用户提出的确定性检查条件 |
| top_p=1 | 959 次请求全部为 **0.8** | 不满足 |
| system 完全一致 | 所有请求只有一个相同的 system 字节串 | 满足 |
| user 完全一致 | 同一题跨重复、跨语义尝试的 user 等于同一原始题目 | 满足；不是要求不同题的 user 相同 |
| few-shot 相同且顺序固定 | 无 few-shot；消息恰为 system、user 两条 | 不存在示例抽样或排序变化 |
| max_tokens 固定 | 959 次全部 **3600** | 本次实际满足 |
| 截断恢复容量 | 配置允许升至 6144，但这 959 次没有使用 | 不能把预设恢复容量说成实际变化 |
| penalties | presence=0、frequency=0 | 全部相同 |
| provider seed | 未发送 | 算法 Seed42 不等于固定供应商采样 |
| Test 并发 | 冻结配置为 16 | 不是后来实验的 Solver96 |
| 网络重试 | 所选请求链为 0 | 不能用网络重试解释本批 flip |

这里只确认持久化、发送前的请求参数和返回正文。供应商是否在内部重路由、
忽略参数或使用不同实现，客户端证据不能完全回答。

## 4. 可见解题输出与解析问题

逐题检查 54 道 flip 的可见推导、最终答案行与提取结果，按主要可见差异分类：

| 类别 | 独立题数 / 54 | 证据解释 |
|---|---:|---|
| 可见推导或题意理解变化 | 47 | 存在移项符号、容斥、约束分支、图形解释、系数、计数等实际差异 |
| 历史边界提取缺陷 | 4 | 末尾显式答案正确，但前面的自然结论吞掉后续标签 |
| 推导与最终答案行不一致 | 2 | 正确结果已出现在推导中，最终行丢失因子或另写数值；提取忠实保留了该行 |
| 矩阵序列化／评分敏感 | 1 | 矩阵计算一致，但最终行变为空格列表或逗号列表，V7 不将其视为相同矩阵 |

这是输出证据分类，不是对模型不可见内部思维的测量，也不是已证实的采样参数因果分解。

### 旧解析器缺陷的具体机制

冻结 [`math_flexible_answer.py`](https://github.com/mmmmyyyxx/independent_gepa_repro/blob/df19bf84ddfe093f0b0c4475293d4fd7026f7cb9/src/independent_gepa/single_prompt_math/math_flexible_answer.py#L88)
的 `_complete` 遇到“以行内数学包装开头、后面还有说明文字”的自然结论时，
要求整个字符串末尾关闭数学包装。`_records` 的续行逻辑
（第 177–182 行）继续读到后面的显式标签，再通过 `skip` 将这些行跳过。
因此完整输出被判为 `MALFORMED_FINAL_BOUNDARY`，而末尾合法标签没有独立处理。

四个 flip ID 合计 5 条终端观测受到该缺陷影响：repeat1/2/3 分别 1/3/1 条。
单独隔离原输出中已有的末尾标签，再用同一历史 parser/V7 评分器离线检查，
这 5 条均有效且正确。**这只是缺陷诊断，绝非重写历史成绩。**

所有无效尝试共 73 次：34 次边界异常、39 次歧义载荷；涉及 27 条逻辑观测、15 道题。
隔离已有末尾标签可使其中 33 次有效，32 次判对。
此外，终端无效的另外 9 条来自三个非标准数学表达式题型：
字母集合索引 696、词语分类索引 2853、星期索引 3526。
其中后两题的 6 条终端文本与题意及参考词语相符，但数学表达式过滤器仍拒绝；
它们三次都无效，**不会解释正确性 flip，却说明旧 parser 的任务覆盖有缺口**。
索引 696 的字母集合本身也不同于参考，不能把其无效一概视为误扣正确答案。

### 用户提出的选项格式检查

独立合成测试，不使用或泄露真实题目：

| 合成输出 | 历史 V7 行为 |
|---|---|
| `The answer is (C)` | 有效；对合成参考 C 判对 |
| `C.` | 无显式声明，判为无效；没有错误映射到别的字母 |
| `\boxed{C}` | 有效；对合成参考 C 判对 |
| `Final answer: C` | 有效；对合成参考 C 判对 |

这说明不能宣称旧提取函数对所有答案格式“完全正确”。
这些规则属于历史 V7；当前唯一生产评分器已经替换，**本任务没有恢复或修补旧评分器**。

## 5. 并发、重试和供应商线索

冻结运行器按稳定行输入 `ThreadPoolExecutor.map`，返回仍为输入顺序；
[`Runtime.prediction`](https://github.com/mmmmyyyxx/independent_gepa_repro/blob/df19bf84ddfe093f0b0c4475293d4fd7026f7cb9/src/independent_gepa/single_prompt_math/runtime.py#L275)
使用包含尝试、repeat、phase/split、Prompt、题目 ID、参考散列及实际请求的 key。
本次独立重算全部 900 个 key，沿请求→回执→供应商正文→语义尝试→最终观测核对，
959 个供应商响应 ID 也全部唯一。没有发现本地按完成顺序误配给题目的证据。
这不能证明供应商内部绝不会串请求，但本地 artifacts 不支持该解释。

重试是无效输出恢复，最多 4 次，首个有效结果即停止；有效答错不会自动重试。
三次分别有 9/12/6 条首答无效，5/6/2 条最终恢复有效，其中 5/5/1 条最终判对。
54 道正确性 flip 中，48 道三次都是首答有效，不能归因于本地语义重试。
全部响应无截断，所选请求链无网络重试，因此本批没有容量升级或网络重试引起的额外采样。
解析器误拒会触发新语义作答，确实可能改变其后的观测；不能推断未保存的另一种结果。

供应商返回过 `gpt-4o-mini` 和 `gpt-4o-mini-2024-07-18` 两种 model 字段，
也有多个 fingerprint。三次两两共 900 个末答配对中，870 对 fingerprint 相同，
已有 107 对正确性 flip；另 30 对 fingerprint 不同，只有 1 对 flip。
因此“看到了不同 fingerprint”不足以解释本批变化；相同 fingerprint 也没有保证输出相同。
这些字段不是权重或部署身份的证明，不能据此断言被换模型或其因果贡献。
repeat2 的付费观测早于后补的 repeat1/3，repeat 编号也不是严格的生成时间顺序。

## 6. 处理建议与边界

1. 保留旧成绩和本次差异清单，将其明确标为 0.2/0.8 下、含旧 V7 格式效应的历史结果。
   不能把 54 道全部描述为纯模型数学能力随机变化。
2. 若要回答用户提出的确定性问题，需要另行冻结新的同模型控制：temperature=0、
   top_p=1、固定实际容量、完全相同的消息、无 few-shot 随机化，记录每次请求及原始响应。
   本次尚未执行，不能从历史数据外推“这样仍有大量 flip”。
3. 新控制只使用当前唯一评分合同，先离线验证选项、数值、集合、矩阵及输出包装。
   GPT-4o-mini 旧 baseline 与目前默认 Qwen Solver、新评分器不能混在一起宣称严格配对。
4. 初次响应与恢复后结果应同时保留，分别报告正确性、有效性、最终行格式和恢复量。
   同 Prompt 对照的测量必须避免把同一份缓存当作独立重复；本历史 baseline 没有跨重复共享缓存。
5. 不因本次审计自动更改温度、解析器、Prompt、旧实验成绩或授权；任何新的真实控制需新冻结与授权。

审计核验见 [verification.json](verification.json)、[parser_replay.json](parser_replay.json)、
[末尾标签隔离诊断](invalid_label_projection.json)、[合成格式测试](fixture_checks.json)。
全程零模型 API；900 条旧成绩保持不变；未提交、未推送。
